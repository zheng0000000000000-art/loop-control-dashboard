# DONE-CRITERIA — "됐다"가 무슨 뜻인가

세 층이 있고 층마다 판정자가 다르다. **이 문서는 판정하지 않는다. 누가 판정하는지를 가리킨다.**

체크리스트를 여기 옮겨 적지 않는 이유: 두 벌이 되면 한쪽만 낡는다. 그리고 낡은 쪽이
더 읽기 좋아 보인다. `docs/context/RUNTIME-INDEX.md`를 손으로 쓴 문서보다 믿으라는 규칙과 같다.

## 1. 태스크 하나가 됐다

**판정자**: 프로그램. `verify_task`의 exit code와, 실행한 세션과 **다른** 세션의 승인(`ADR-020`).

- 인수 기준은 태스크의 `acceptanceCriteria`에 있다. 태스크마다 다르다.
- 자기보고는 증거가 아니다. 판정 세션은 하네스를 **직접 재실행해 대조**한다.
- 납품이 없으면 통과하지 못한다. 커밋했든 안 했든 센다(`src/delivery-gate.js`).

여기는 이미 코드가 강제한다. 사람이 할 일이 없다.

## 2. 백로그 항목 하나가 됐다

**판정자**: 그 항목이 만든 보드 태스크가 `DONE`이 되는 것. 항목의 `status`가 `DONE`으로 간다.

- 항목의 인수 기준은 `BACKLOG.json`의 `acceptanceCriteria`에 있다.
- 우선순위가 왜 그 숫자인지는 `BACKLOG-POLICY.md`가 정하고 `backlog-policy-check.ps1`이 강제한다.
- **백로그가 비는 것은 "다 됐다"가 아니다.** 꺼낼 게 없다는 뜻이다.
  그래서 마르기 전에 폰으로 알린다(`backlog-refill.ps1`, 남은 2건 이하).

## 3. Phase 0이 됐다 — `HS-GATE-P00`

**판정자**: `ADR-011` §4의 A/B/C 조건. **여기 옮겨 적지 않는다 — 그 문서를 봐라.**

핵심만 옮기면, 사람이 2026-07-12에 직접 정의했다:

> `HS-GATE-P00`은 "검사가 다 있다"로 통과하지 않는다.
> **"로컬 실행자로 한 바퀴가 실제로 돈다"**로 통과한다.

그리고 그 한 바퀴에는 **시뮬레이션이 포함된다.** 그래서 시뮬레이션 게이트가 실제로 가르는지를
다루는 일은 `P2` 제품 기능이 아니라 `P0`다(`BACKLOG-POLICY.md` §1의 "자주 틀리는 곳").

## 4. P0의 성공을 무엇으로 재는가

**판정자**: 사람. `INTENT-DIGEST §2`가 네 가지를 든다.

| 지표 | 목표값 | 상태 |
| --- | --- | --- |
| 토큰 절감 | **(미정 — 사람이 정한다)** | 실측 있음: 메타 루프 1회 49,281 토큰(그중 실제 작업 193). 목표선이 없다 |
| 작업 안정성 | **(미정 — 사람이 정한다)** | 실측 있음: 게이트 통과율·회로 차단 횟수를 세고 있다. 어디까지가 합격인지 없다 |
| 재사용성 | **(미정 — 사람이 정한다)** | 스킬·하네스 재사용 횟수를 기록 중. 기준선 없다 |
| 실행 속도 | **(미정 — 사람이 정한다)** | 한 바퀴 실측 있음. 목표 없다 |

**비워 둔 것은 빠뜨린 것이 아니다.** 이 네 줄의 목표값은 프로그램이 정할 수 없다 —
정하게 두면 루프가 자기가 잴 수 있는 것을 목표로 삼는다. `SIMULATION-CHECKLIST-v1 §7`이
지표의 상·하한과 목표 문장과 제약을 사람 몫으로 둔 것과 같은 이유다.

**채워지기 전까지 "P0가 됐다"고 말하지 않는다.** 이것이 이 문서의 유일한 판정이다.

## 5. 경매장 시뮬레이션이 됐다

**판정자**: 사람. 사용자가 말한 목표는 *"특정 자본을 가지고 정보가 제한된 상태에서
특정 수치만큼 돈을 벌려면 어떻게 하면 될지"*다.

| 값 | 상태 |
| --- | --- |
| 시작 자본 | **20,000** (사람 결정, 2026-07-29) |
| 목표 | **12회차에 100,000 이상** (사람 결정, 2026-07-29) |
| 최종 경매 적 자본 | **120,000 ~ 150,000** (사람 결정, 2026-07-29) |
| 상회 업그레이드 품목 | **(미정)** — 아직 정하지 않았다. 성장 지렛대가 빠진 채로 재는 것임을 감안한다 |
| 정보 제한의 정도 | 부분 실측: 감정가 0 → `informed` +107%, 0.05 → −35%, 0.15 → −96%. **어디가 맞는 설정인지는 미정** |

여기서 지금 걸려 있는 것: **밸런스 목표는 "정보를 합쳐 쓰는 것에 보상"이라고 말하는데,
현재 설정은 정보가 순손실이다**(감정가가 이득을 잡아먹는다). 둘 중 하나가 틀렸고
어느 쪽을 고칠지는 사람 결정이다.

### 1차 시뮬레이션의 목표는 달성이 아니라 진단이다 (2026-07-29)

사람이 말했다 — *"처음 돌리는 거니까 현재 구조에서 뭐가 문제인지 파악부터"*.
그러므로 **1차의 성공은 100,000 을 넘기는 것이 아니라, 왜 못 넘기는지를 수치로 대는 것**이다.
못 넘겼다는 결과 자체는 실패가 아니다. 이유를 못 대는 것이 실패다.

## 이 문서를 고쳐야 할 때

- 사람이 §4나 §5의 **(미정)** 을 채웠을 때 — 그때 이 표를 갱신하고 `BASELINE-CHANGES`에 남긴다.
- 판정자가 바뀌었을 때(예: 승인 규칙 변경) — 가리키는 곳을 고친다.
- **조건이 늘었다고 여기 적지 마라.** 조건은 판정자가 있는 곳에 적는다.
