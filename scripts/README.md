# 조율자 하트비트 — 멈춘 것을 사람이 먼저 알게 한다

## 왜 있는가

**조율 세션은 턴 사이에 시계가 없어서 자기가 멈춘 것을 스스로 모른다.**
2026-07-27에 `05:14`부터 `10:51`까지 **5시간 38분** 공백이 있었고, 그 사이 사용자가 대화 채널에
남긴 글 두 개를 아무도 읽지 않았다. 조율자는 이어서 일하는 것처럼 느꼈다.

**사람이 물어봐서 알았다. 그건 감시가 아니다.**

## 계약

| 주체 | 할 일 |
| --- | --- |
| **조율자** | 의미 있는 작업을 할 때마다 하트비트 파일을 갱신한다 |
| **감시자**(스케줄 작업, 15분마다) | 하트비트가 **25분** 이상 낡으면 ntfy로 알린다 |

하트비트 파일: `C:\NHN Project\_ops\coordinator-heartbeat.json`

```json
{ "at": "2026-07-27T02:00:00Z", "note": "무엇을 하던 중이었나", "session": "..." }
```

## 판정 규칙

- **판정은 파일의 나이 하나다.** 프로세스 존재 여부로 판정하지 않는다 —
  프로세스가 살아 있어도 일을 안 할 수 있고, 그건 "돌고 있다"의 증거가 아니다.
- **같은 정지를 다시 알리지 않는다.** `<heartbeat>.alerted` 표식으로 막는다.
  같은 정지로 계속 울리면 사람이 알림 자체를 끈다.
- 하트비트가 다시 살아나면 표식을 지운다.

## 실측으로 확인한 것 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| 하트비트 방금 갱신 | `alive age=0m`, exit **0**, 알림 없음 |
| 40분 전으로 위조 | `would-alert`, exit **1** |
| 실제 발송 후 ntfy에서 되읽기 | `조율자가 42분째 조용하다. 마지막 작업: …` |
| 스케줄 작업 1회 실행 | `LastTaskResult: 0` |

## 만드는 과정에서 밟은 인코딩 함정 둘

1. **`-Body ([Text.Encoding]::UTF8.GetBytes(...))`** → 알림 **제목만 오고 본문이 빈 문자열**로
   도착했다. UTF-8 임시 파일 + `-InFile`로 바꿔 해결.
2. **BOM 없는 `.ps1`** → PowerShell 5.1이 ANSI로 읽어 **스크립트 안 한글이 깨졌다**(`議곗쑉?먭?`).
   JSON에서 읽은 한글은 멀쩡했기에 원인이 스크립트 파일임이 갈렸다. **UTF-8 BOM**을 붙여 해결.

둘 다 **터미널 표시가 아니라 ntfy에서 되읽어** 확인했다 —
`skills/common/powershell-encoding`이 말하는 그대로다. *"터미널 표시만 보고 판단하지 마라."*

## 알림이 가는 곳

`server/appsettings.json`의 `Ntfy.Topic`. 스크립트가 그 값을 읽으므로
토픽을 바꾸면 감시자도 따라간다 — **두 벌로 두지 않는다.**

## 끄는 법

```powershell
Unregister-ScheduledTask -TaskName 'CoordinatorHeartbeatWatch' -Confirm:$false
```
