# 씬 명세 — 경매장 (scene-auction)

**이 문서 하나로 이 화면을 구현할 수 있어야 한다.** 다른 문서를 안 봐도 되게 값을 여기 옮겨 적었다.
값의 출처는 `docs/plan/SIMULATION-STATUS.md` 6절이고, 괄호로 소절 번호를 달았다.
**출처가 없는 값은 §8에 따로 모았다 — 그건 아직 아무도 안 정한 값이다.**

- 상태: 그레이박스. **에셋 없음, 자리만.**
- 판정: 그림이 아니라 **exit code**. §9의 검사가 전부 통과하면 이 씬은 된 것이다.

---

## 1. 이 화면이 하는 일

하루치 경매 8건을 순서대로 붙인다. 플레이어는 물건마다 **감정할지 / 얼마를 걸지 / 넘길지**를 정한다.
여덟 건이 끝나면 재고를 팔아 정산하고 하루가 끝난다.

**이 화면의 긴장은 하나다** — 기준가는 보이는데 품질과 시세는 안 보인다.
그 차이를 돈 주고 사는 것이 감정이다.

---

## 2. 화면 배치 (그레이박스)

두 단. 좁아지면 한 단으로 접는다(820px).

```
+---------------------------------------+  +------------------+
|  L1  출품 목록 · 8행                   |  |  R1  플레이어     |
|      각 행: 번호 / 등급·계열 / 결과     |  |  R2  보관 칸      |
|      부속: 기저가 · 시작가 · 감정결과   |  |  R3  현재 물건    |
|      현재 행은 강조, 지난 행은 흐림     |  |      + 행동 버튼  |
|                                       |  |  R4  경쟁자       |
|                                       |  |  R5  장부·정산    |
+---------------------------------------+  +------------------+
```

| id | 영역 | 요소 |
| --- | --- | --- |
| `L1` | 출품 목록 | 행 8개. 각 행 = 순번 · 등급명 · 계열명 · 기저가 · 시작가 · (감정했으면)추정가 · 결과배지 |
| `R1` | 플레이어 | 현금 · 누적 지출 · 누적 회수 |
| `R2` | 보관 칸 | 빈 칸 `storage`개. 채워지면 등급명 표시 |
| `R3` | 현재 물건 | 등급·계열 · 기저가 · 시작가 · 감정 비용 · **손익분기선** · 행동 버튼 4개 · 결과 문구 |
| `R4` | 경쟁자 | 봇 3인의 **입찰 상한**(자본 아님). 상한만 공개한다 |
| `R5` | 장부 | 지출 항목 목록 → 정산 결과 |

**공개/비공개**는 규칙이다. 화면이 정하는 게 아니다.

| 값 | 공개 | 이유 |
| --- | --- | --- |
| 등급 · 계열 · 기저가 · 시작가 | **공개** | 기저가가 손익분기선이다(6.14). 판단의 기준선 |
| 봇 **입찰 상한** | **공개** | 6.7의 상한은 관측 가능한 규칙이다 |
| 품질 k | 감춤 | 감정으로만 좁힌다(6.2) |
| 시세 M | 감춤 | 계열 지수만 관측 가능(6.13). 개별 잡음은 끝까지 안 보인다 |
| 봇의 이번 입찰액 | 감춤 | 낙찰 판정 시점에 굴린다. 미리 보이면 정보가 공짜다 |

## 3. 상태

이 화면이 읽고 쓰는 경로 전부다. **여기 없는 경로를 이 화면이 만지면 안 된다.**

| 경로 | 형 | 초기값 | 쓰는 곳 |
| --- | --- | --- | --- |
| `player.cash` | 정수 | `20000` (6절) | 감정 · 입찰 · 정산 |
| `player.spent` | 정수 | `0` | 감정 · 입찰 |
| `player.earned` | 정수 | `0` | 정산 |
| `shop.stage` | 1\|2\|3 | `1` | (이 화면은 안 바꿈) |
| `shop.storage` | 정수 | `4` (6.6 · 1단계) | (이 화면은 안 바꿈) |
| `inventory[]` | 물건[] | `[]` | 입찰 성공 시 push · 정산 시 비움 |
| `auction.day` | 정수 | `1` | (이 화면은 안 바꿈) |
| `auction.lots[]` | 물건[] | 생성 8건 | 진입 시 1회 |
| `auction.index` | 0..8 | `0` | 입찰 · 넘김 |
| `auction.currentLot` | 물건\|null | `lots[0]` | `index` 파생 |
| `auction.bots[]` | 봇[] | 생성 3인 | 진입 시 1회 |
| `auction.appraised` | {물건id: 감정} | `{}` | 감정 |
| `auction.log[]` | 기록[] | `[]` | 모든 행동 |
| `auction.settled` | 불리언 | `false` | 정산 (재진입 방지) |

**물건**은 이렇게 생겼다.

```
id · day · index · gradeId · gradeName · series
basePrice   공개
startBid    공개
quality     감춤 (k)
demand      감춤 (M)
trueSale    감춤 = basePrice x quality x demand
```

## 4. 행동

| 행동 | 전제 | 효과 | 막히는 경우 |
| --- | --- | --- | --- |
| `appraise` 감정 | 현재 물건 있음 · 아직 감정 안 함 · 현금 ≥ 감정비 | 현금·지출 갱신 · `appraised[id]` 기록 | 현금 부족 → 문구만, 상태 불변 |
| `bid` 입찰 | 현재 물건 있음 | 아래 판정 | 아래 |
| `pass` 넘김 | 현재 물건 있음 | `index += 1` | — |
| `settle` 정산 | `index === 8` · `settled === false` | 재고 전부 판매 · 재고 비움 · `settled = true` | 두 번째 호출은 **아무것도 안 한다** |

**입찰 판정 순서.** 이 순서가 결과를 정한다.

```
1. 봇 입찰을 지금 굴린다        bids = bots.map(botBid)
2. 최고 봇 입찰                best = max(bids)
3. 최소 인상폭                 inc = max(100, round(best x 증분율))
4. 필요 금액                   needed = max(startBid, best + inc)
5. playerBid >= needed 인가?
   아니오 -> 패찰
   예 -> 6번
6. needed <= cash 인가?  아니오 -> "현금 부족", 지나감(못 삼)
7. 재고 여유 있나?       아니오 -> "보관칸 없음", 지나감(못 삼)
8. 낙찰. cash -= needed. 재고에 넣는다
9. index += 1  (패찰·못삼·낙찰 전부)
```

**낙찰가는 `playerBid`가 아니라 `needed`다.** 공개 호가라서 그렇다 —
경쟁자 위로 최소폭만 올려 산다. 이걸 `playerBid`로 하면 정직한 사람이 손해를 본다.

## 5. 규칙과 값

### 5.1 물건 생성 (씬 진입 시 1회)

```
등급     가중 추첨
품질 k   가중 추첨
계열     6종 균등
계열지수 I  1일차: 1 + N(0, 0.1065)
            이후: 1 + 0.7 x (전일 I - 1) + N(0, 0.0761)     (6.13 AR(1))
수요 M   = 1.05 + β(등급) x (I - 1) + N(0, 0.0870)          (6.13)
trueSale = basePrice x k x M                                (6.2)
```

| 등급 | 가중치 | 기저가 | β (6.13) |
| --- | --- | --- | --- |
| 일반 common | 0.300 | 1,500 | 0.27 |
| 레어 rare | 0.430 | 4,000 | 1.00 |
| 에픽 epic | 0.195 | 12,000 | 2.09 |
| 전설 legendary | 0.075 | 25,000 | 3.64 |

| 품질 k | 이름 | 가중치 |
| --- | --- | --- |
| 0.60 | 손상 | 15 |
| 0.90 | 보통 | 40 |
| 1.10 | 양호 | 25 |
| 1.35 | 수려 | 15 |
| 1.60 | 완품 | 5 |

**E[k] = 1.0075 · sd[k] = 0.2585.** 가중치를 바꿔도 **E[k]는 1.00 ±0.02 안에 둔다**(6.2) —
벗어나면 경제 총량이 흔들려 아래 곡선이 전부 무효가 된다.

계열 6종: 청자 · 목기 · 금속 · 서화 · 석물 · 직물 (6.4)

### 5.2 봇 (6.7 · 6.15)

```
숙적 자본 = round(25000 x 1.155^day)      1일차 28,875 · 12일차 140,904
뜨내기 자본 = round(숙적 자본 x 0.4)
입찰 상한 = 자본 x 0.15
봇 입찰 = round(min(basePrice x (1 + N(0, 추정오차)), 입찰 상한))
```

### 5.3 감정 (6.3)

```
비용 = round(basePrice x 0.03)
추정 = round(trueSale x (1 + U(-1,1) x 오차))
오차 = 1~3일차 0.35 · 4~6일차 0.20 · 7~12일차 0.10
```

### 5.4 정산 (6.14)

```
판매액 = round(trueSale x (1 - 0.05))          수수료 5%
```

**손익분기선 = 기저가다.** `E[k] x E[M] x (1 - 수수료) = 1.0075 x 1.05 x 0.95 = 1.0050`.
기저가에 사면 본전이라는 뜻이고, **화면은 이 선을 보여줘야 한다.**

### 5.5 난수

**씨앗 고정.** 같은 씨앗이면 같은 판이 나와야 한다 — 재현이 안 되면 잰 것이 아니다.
씨앗은 밖에서 주입한다(`?seed=`). 물건 생성용과 진행용(감정·봇입찰) 흐름을 **나눈다** —
안 나누면 감정을 한 번 더 하는 것만으로 봇 입찰이 바뀐다.

## 6. 이 화면이 사람에게 말해야 하는 것

명세로 못 박는다. **없으면 사람이 이 화면을 쓸 수 없다.**

| 반드시 화면에 있어야 하는 것 | 왜 |
| --- | --- |
| **손익분기선** (= 기저가) | 이게 없으면 얼마가 비싼 값인지 알 방법이 없다 |
| **걸 만한 값 제안** | 빈칸에 숫자를 쓰라고만 하면 아무도 못 쓴다. 감정했으면 `추정 x 0.95 x 0.70`, 안 했으면 `기저가 x 0.70` |
| **봇 입찰 상한** | 경쟁이 될지 안 될지가 이걸로 정해진다 |
| **패찰 사유** | "얼마에 졌는지"를 안 보이면 다음 판에서 배울 게 없다 |
| **정산에서 매입가 대비 손익** | 좋은 판단이었는지가 여기서만 확인된다 |

## 8. 아직 아무도 안 정한 값 — **구현자가 고르면 안 된다**

6절에 없다. 임시로 아래를 넣어 굴려봤고, **하나가 게임 전체를 정한다는 것이 실측으로 나왔다**(6.16·6.18).

| 값 | 임시값 | 없으면 안 되는 이유 |
| --- | --- | --- |
| **시작가 / 기저가** | 0.5 | 경매를 시작할 수가 없다 |
| 최소 인상 비율 | 0.10 | 낙찰가를 정할 수가 없다 |
| 봇 추정 오차 | 0.20 | 봇이 얼마를 부를지 정할 수가 없다 |
| 뜨내기 인원 | 2 | 6.15는 세기만 정하고 머릿수를 안 정했다 |

**시작가 하나가 12회차 목표 도달률을 71% ↔ 0% 로 흔든다.**

| 시작가/기저가 | 12회차 중앙값 | 목표 100,000 도달 |
| --- | --- | --- |
| 0.50 | 122,442 | 70.8% |
| 1.00 | 11,417 | 0.0% |

그리고 지금 값(0.5)에서는 **감정하는 쪽이 눈 감고 사는 쪽에게 진다**(6.18) —
낙찰가가 기저가의 62%에 형성돼서 무엇을 사든 이미 남는 장사이기 때문이다.
낙찰가/기저가가 0.95로 올라가면 같은 감정이 `-6.7%p → +2.7%p`로 돌아선다.

**구현은 임시값으로 진행해도 된다. 다만 이 값들을 `PROVISIONAL` 로 따로 묶어
확정값과 섞지 않는다.** 섞으면 다음 사람이 6절 값으로 오해한다.

## 9. 판정 — 이걸 다 통과하면 이 씬은 된 것이다

**그림으로 판정하지 않는다.** 아래를 검사로 만들고 exit code로 본다.

### 9.1 규칙이 문서를 재현하는가

```
E[k] = 1.0075 (±0.0001)                sd[k] = 0.2585 (±0.0005)
E[k] x E[M] x (1-수수료) = 1.0050       숙적 12일차 자본 = 140,904
숙적 1일차 자본 = 28,875                뜨내기/숙적 = 0.40
입찰 상한 = 자본 x 0.15                 감정비 = 기저가 x 0.03
감정 오차 1일차 0.35 · 7일차 0.10       legendary β / rare β = 3.64
표본 E[k] ≈ 1.0075 · 표본 E[M] ≈ 1.05   하루 총 기저가 ≈ 51,080
```

### 9.2 한 판이 성립하는가

```
물건 8건이 나온다                       봇 3인이 선다
낙찰가는 늘 시작가 이상이다              현금이 음수로 안 간다
장부가 맞는다: 시작 - 지출 + 회수 = 현금
보관칸을 안 넘긴다                       같은 씨앗은 같은 판을 낸다
다른 씨앗은 다른 판을 낸다
```

### 9.3 화면이 상태와 안 갈라지는가

DOM 없이 클릭 경로를 태워서 잰다.

```
초기 현금 = 20,000                      보관칸 = 4
8건이 그려진다                          8건을 다 지나면 버튼이 닫힌다
정산이 한 번만 돈다
음성: 정산을 다시 불러도 현금이 안 늘어난다
음성: 현금보다 비싼 낙찰은 재고에 안 들어간다
음성: 보관칸이 찼으면 낙찰해도 못 산다
```

### 9.4 헤드리스와 화면이 같은 값을 내는가

**같은 씨앗·같은 정책으로 헤드리스 하네스와 화면이 같은 최종 현금을 내야 한다.**
안 맞으면 화면이 규칙을 딴 데서 가져온 것이다.
