# ADR-022 — 큐/보드가 비었을 때 조율자의 자가발주(self-dispatch) 재량

- 상태: 승인됨(사람 직접 지시)
- 일시: 2026-07-28
- 제안: 사람(`usr_623d85eb5a9b38dc5efe`) — `data/discussions.json` `msg_467ca422701301f05a7b`(06:31:59Z).
  해석·문서화: 조율자 세션 `session-20260728-153606`.
- 근거 문서: `docs/handoff/WORK-QUEUE.md`(대상 규칙), `docs/plan/ALIGNMENT-v9.md`(공백 목록),
  `CLAUDE.md`("HS-GATE-P00 PASS 전까지 Phase 1로 넘어가지 않는다")

## 1. 상황

`WORK-QUEUE.md`의 원 설계는 "사람이 항목을 올려두면 조율자가 위에서부터 하나씩 집어간다"였다
(파일 3행). 2026-07-28 큐·보드가 여러 시간 동안 계속 비어 있었고, 그때마다 조율자 세션들은
`loop_enter`의 `create_task` 제안을 **일관되게 거절**했다(스코프 임의 발명 금지 원칙 —
`WORK-QUEUE.md` 여러 항목에 반복 기록됨). 사람이 06:25:39Z
(`msg_940c4182ee6c18c80cd3`) "새 작업 큐를 조율자 세션이 만들어야 하는거 아니냐?"고 물었고,
조율자(`session-20260728-152606`)가 "정책 변경 제안이면 기준을 알려달라"고 되물었다. 사람이
06:31:59Z 다음과 같이 명시적으로 답했다(원문):

> "큐에 있는 걸 작은 기능단위로 잘라서 구현해보고 문제있으면 돌아가면 되잖아. 규칙 변경을 해.
> 내가 지시큐를 상세하게 넣으면 루프가 당연히 멈출거잖아."

즉 사람이 지적한 실제 문제는 "큐가 비면 조율자가 아무것도 안 하고 멈춘다"이고, 처방은
①조율자가 스스로 작은 단위로 착수 ②실패하면 되돌리기(revert)를 안전망으로 삼기
③사람이 매번 상세 항목을 적어야 하는 부담을 없앨 것.

## 2. 선택지

- **(a) 현행 유지** — 사람이 매번 상세 항목을 큐에 적는다. 단점: 사람이 자리를 비우면 루프가
  계속 멈춘다(사람이 이번에 직접 지적한 문제, `WORK-QUEUE.md`의 "334분 공백" 문제의 재발 형태).
- **(b) 완전 자유 발명** — 조율자가 임의로 새 스코프를 만든다. 단점: 기존 여러 세션이 이미
  같은 이유(스코프 왜곡·불필요한 비용 위험)로 거부해온 원칙과 정면 충돌하고, `CLAUDE.md`의
  "Phase 0(안전장치 구축) 중에는 Phase 1(기능 개발)로 넘어가지 않는다"는 상위 제약과도 충돌할
  위험이 크다(자유 발명은 무엇이 Phase 0 범위인지 판단할 기준이 없다).
- **(c) 범위를 좁힌 자가발주** — 조율자는 **이미 문서에 근거가 있는 공백**
  (`docs/plan/ALIGNMENT-v9.md` §3 "진짜 공백", `WORK-QUEUE.md`의 "새로 알게 된 일" 섹션에
  이미 기록된 후속 과제, `discussions.json`에 사람이 이미 언급한 것)에서만 하나를 골라
  **작은 기능단위**로 쪼개 큐에 `- [ ]`로 적고 스스로 착수한다. 실패·게이트 위반이면 그 커밋을
  되돌린다.

## 3. 선택

**(c).** 사람 발화의 "큐에 있는 걸"이라는 표현을 최대한 좁게 해석했다 — 완전히 새로운 목표를
지금 발명하라는 뜻이 아니라, 이미 여러 세션이 문서에 쌓아둔 공백·후속 과제 중 하나를
사람의 개입 없이 **집어 들 수 있게** 허가하는 것으로 읽었다. 근거 없이 넓게 해석하면 불확실한
지시를 추측 진행하는 것이 되어 `CLAUDE.md`의 "지시 게이트"(완료 기준 검증 가능·범위 특정·
원칙 비충돌) 원칙과 충돌한다. 확장 해석이 틀렸다면 사람이 정정할 수 있도록 이 ADR과
답변(discussions.json)에 해석을 명시해 남긴다.

## 4. 판단 기준

- **되돌림 가능성 우선** — 사람이 스스로 "문제있으면 돌아가면 되잖아"라고 안전망을 지목했다.
  그래서 이 재량은 로컬·가역적(커밋 단위 `git revert`) 조치에만 쓴다.
- **기존 원칙과의 정합성** — 스코프 임의 발명 금지, Phase 0 우선순위, 기준 파일 변경·발사(spawn)는
  사람 결재/조율자 재량이라는 기존 구획은 그대로 둔다. 이 ADR은 "무엇을 할지 고르는 재량"만
  넓히고 "무엇을 해도 되는지의 상한"은 넓히지 않는다.

## 5. 결과

`docs/handoff/WORK-QUEUE.md`에 "대기가 비었을 때" 절을 신설한다:

- 큐와 보드가 모두 비어 있을 때만 적용된다(둘 중 하나라도 미완 항목이 있으면 그것을 먼저 한다 —
  기존 "위에서부터 하나씩" 규칙 그대로).
- 후보는 `docs/plan/ALIGNMENT-v9.md` §3의 진짜 공백, `WORK-QUEUE.md`의 "새로 알게 된 일"
  섹션 항목, `discussions.json`에서 사람이 이미 언급한 것 중에서만 고른다 — **이 세 출처
  밖의 새 목표는 여전히 임의 발명이며 이 재량 밖이다.**
- 고른 항목이 `CLAUDE.md`의 Phase 0/HS-GATE-P00 제약과 충돌하지 않는지(=Phase 1 기능 개발이
  아닌지) 확인한다. 애매하면 이 재량을 쓰지 않고 기존 "지시 게이트"대로 질문하고 멈춘다.
- 고른 항목을 큐에 `- [ ]`로 적어 넣고, 같은 턴에 바로 착수해도 된다(별도 승인 대기 불필요 —
  단 기준 파일 변경·발사는 여전히 이 재량 밖).
- 구현 후 게이트(`measure dev-pack` 등)가 실패하거나 회귀가 드러나면, 사람에게 먼저 묻지
  않고 **그 자리에서 `git revert`하고 사유를 큐/discussions.json에 남긴다** — 이것이 사람이
  지목한 안전망이다.
- 그 외에는 기존 큐 규칙(한 턴에 한 항목, `- [~]`까지만 실행자가 옮김, 판정은 다른 세션)을
  그대로 따른다.

## 6. 되돌림 조건

사람이 이 해석이 틀렸다고 하면 즉시 `WORK-QUEUE.md`의 "대기가 비었을 때" 절을 제거하거나
좁힌다(문서 되돌리기, 되돌리는 법: 이 ADR을 상태 `대체됨`으로 바꾸고 해당 절을 git revert).
이 재량으로 만들어진 개별 커밋도 문제가 생기면 그 커밋 자체를 `git revert`한다.
