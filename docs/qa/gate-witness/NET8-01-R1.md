## 2. 무엇을 했나

`server/Harness/`의 **18개 파일**이 각자 만들던 `JsonSerializerOptions`를 한 벌로 모았다
(지시서는 17개로 적었으나 실측 18개 — `StateTransitionCallsiteCheckCli.cs`가 `WriteOptions`라는
다른 이름을 써서 앞선 집계에서 빠진 것으로 보인다).

새 파일 `server/Harness/HarnessJson.cs` 하나가 정의를 갖는다:

```csharp
internal static readonly JsonSerializerOptions Options = new()
{
    WriteIndented = true,
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,
    TypeInfoResolver = new DefaultJsonTypeInfoResolver(),
};
```

**18개 선언의 값은 전부 같았다.** 다른 값이 있으면 갈아타지 말라고 돼 있었는데, 없었다.

### 컨테이너 실측 (지시서 §4 — 로컬 결과는 증거가 아니다)

`git clone`은 커밋된 것만 가져가므로 `tar`로 작업 트리를 복사해 쟀다(지시서 §4 주의 사항).

**핵심 — `hs-scan`:**

| | .NET 8 | 출력 |
| --- | --- | --- |
| **수정 전**(`7afe981`) | exit **2** | `JsonSerializerOptions instance must specify a TypeInfoResolver setting before being marked as read-only.` |
| **수정 후** | exit **1** | 매니페스트 기대값. `"candidates": []` |

수정 전 상태는 `git archive HEAD`로 내보내 같은 컨테이너에서 따로 쟀다 — **음성 사례가 실제로 재현된다.**

## 지표는 만족했으나 목적은 미달인 부분

**있다. 셋이다.**

1. **컨테이너의 비-0 exit들을 "정상"이라고 단정하지 않았다.**
   `handoff-integrity`·`scope-check`·`gate-clean` 등이 2를 내는데, 복사본에 `.git`과
   `outputs/`가 없어서라고 **추정**했을 뿐 하나씩 원인을 확인하지 않았다.
   두 런타임이 같다는 것만 확인했다 — 그건 "회귀 없음"의 증거이지 "정상"의 증거가 아니다.

2. **`di-completion-check --gate POST-COMMIT`이 컨테이너에서 exit 1이다.**
   지시서 기대값은 `PASS 22/22`인데 그건 `.git`과 증거 파일이 있는 환경 기준이다.
   **컨테이너에서 POST-COMMIT PASS를 직접 보이지 못했다.** 그것을 실제로 보이는 자리는
   CI(진짜 checkout)뿐이고, 그래서 matrix `"8.0"` 켜기는 **CI가 초록으로 도착한 뒤**로 미뤘다.
   지금 이 보고만으로 다리를 켜면 FAIL-2026-010이다.

3. **지시서가 17개라고 한 것을 18개로 고쳤는데, 지시서를 갱신하지 않았다.**
   `WriteOptions`라는 다른 이름 때문에 앞선 집계가 하나를 놓친 것으로 보이나,
   그 집계를 누가 어떻게 냈는지는 확인하지 않았다 — **주체 미상.**
