# ADR-020 — 승인은 에이전트가 한다. 단, 자기 일은 아니다.

- 상태: 채택
- 일자: 2026-07-27
- 주체: **사용자(결재)** · 조율자 Claude(구현)
- 성격: **완화** — 기준 변경이다. `BASELINE-CHANGES.md`에 함께 남긴다.

## 맥락

`ADR-019`로 실행과 판정을 갈랐다. 그런데 판정의 끝(`approve`/`reject`/`import`)이
여전히 사람 게이트라서, 루프는 **판정 직전까지만** 자동으로 돌고 거기서 멈췄다.
사용자가 원한 것은 자는 동안 도는 것이었으므로 그 지점이 병목이었다.

사용자 지시:

> *"승인 단계에 오면 너가 승인해도 된다고 규칙을 바꿔 그게 맞는 방향 같아"*

## 결정

**`approve`/`reject`/`import`를 에이전트가 할 수 있다.** 조건 하나가 붙는다:

> **실행한 세션과 승인하는 세션이 달라야 한다.**

실행자는 `- [~]`(검토 대기)까지만 옮기고, 승인은 판정 세션이 한다.
판정 세션은 **하네스를 직접 재실행해 대조**하며, 실행자의 자기보고를 근거로 삼지 않는다.

`push`도 허용한다 — 게이트가 전부 통과했을 때만.

## 그대로 사람에 남는 것

| 남기는 것 | 왜 |
| --- | --- |
| **발사(sonnet/codex spawn)** | 비용이 발생한다. 자동으로 태우면 안 된다. |
| **기준 파일 변경** (`blueprint.json`·`workflow-definition.json`·측정 코드) | 여기를 자기가 승인하면 **측정 기준을 고쳐 게이트를 통과**할 수 있다. 그러면 나머지 모든 측정이 의미를 잃는다. 완화의 대가가 완화의 이득보다 크다. |

발사가 필요한 일은 보드에서 제목을 `[사람 게이트]`로 시작해 표시한다.
`coordinator-wake.ps1`이 그 표식을 보고 **안 집는다** — 보이되 집히지 않게 가른다.

## 무엇이 조용히 넘어가게 되는가

솔직히 적는다. 이 완화로 **다음이 사람 눈을 안 거치고 지나간다**:

1. **판정 세션이 잘못 판정한 것.** 실행 세션과 다르다는 것뿐이지 같은 모델이다.
   같은 종류의 착각을 공유할 수 있다. 하네스 재실행이 이걸 부분적으로만 막는다.
2. **완료 조건 자체가 틀린 경우.** 조건을 만족했는지는 대조하지만
   조건이 목적을 담고 있는지는 대조하지 않는다. `ADR-005`의 자진 신고가 유일한 방어다.
3. **반입(import)한 코덱스 산출물의 품질.** 게이트는 통과하는데 설계가 나쁜 경우.

그래서 **`FUSION-OBSERVATION-2W.md`에 이 셋을 관찰 항목으로 넣는다.**
2주 뒤에 실제로 이 셋 중 무엇이 일어났는지 세고, 일어났으면 규칙을 다시 조인다.

## 되돌리는 법

`CLAUDE.md`의 금지 사항에서 이 항목을 원래 문장으로 되돌린다:

```
- **approve/reject/import 대행.** 결재는 사람 몫이다.
- **발사(sonnet spawn)와 push.** 사람 게이트다.
```

그리고 `scripts/coordinator-wake.ps1`의 두 프롬프트에서 승인 허용 문구를 뺀다.
코드 변경은 없다 — 이건 규칙 변경이라 문서와 프롬프트만 되돌리면 원상태가 된다.
