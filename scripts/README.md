# 조율자 운영 스크립트 — 멈추면 알리고, 할 일이 남으면 깨운다

## 왜 있는가

**조율 세션은 턴 사이에 시계가 없어서 자기가 멈춘 것을 스스로 모른다.**
2026-07-27에 `05:14`부터 `10:51`까지 **5시간 38분** 공백이 있었고, 그 사이 사용자가 대화 채널에
남긴 글 두 개를 아무도 읽지 않았다. 조율자는 이어서 일하는 것처럼 느꼈다.

**사람이 물어봐서 알았다. 그건 감시가 아니다.**

## 계약

| 주체 | 할 일 |
| --- | --- |
| **조율자** | 의미 있는 작업을 할 때마다 하트비트 파일을 갱신한다 |
| **감시자**(스케줄 작업, 15분마다) | 하트비트가 **25분** 이상 낡으면 ntfy로 알린다 |

하트비트 파일: `C:\NHN Project\_ops\coordinator-heartbeat.json`

```json
{ "at": "2026-07-27T02:00:00Z", "note": "무엇을 하던 중이었나", "session": "..." }
```

## 판정 규칙

- **판정은 파일의 나이 하나다.** 프로세스 존재 여부로 판정하지 않는다 —
  프로세스가 살아 있어도 일을 안 할 수 있고, 그건 "돌고 있다"의 증거가 아니다.
- **같은 정지를 다시 알리지 않는다.** `<heartbeat>.alerted` 표식으로 막는다.
  같은 정지로 계속 울리면 사람이 알림 자체를 끈다.
- 하트비트가 다시 살아나면 표식을 지운다.

## 실측으로 확인한 것 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| 하트비트 방금 갱신 | `alive age=0m`, exit **0**, 알림 없음 |
| 40분 전으로 위조 | `would-alert`, exit **1** |
| 실제 발송 후 ntfy에서 되읽기 | `조율자가 42분째 조용하다. 마지막 작업: …` |
| 스케줄 작업 1회 실행 | `LastTaskResult: 0` |

## 만드는 과정에서 밟은 인코딩 함정 둘

1. **`-Body ([Text.Encoding]::UTF8.GetBytes(...))`** → 알림 **제목만 오고 본문이 빈 문자열**로
   도착했다. UTF-8 임시 파일 + `-InFile`로 바꿔 해결.
2. **BOM 없는 `.ps1`** → PowerShell 5.1이 ANSI로 읽어 **스크립트 안 한글이 깨졌다**(`議곗쑉?먭?`).
   JSON에서 읽은 한글은 멀쩡했기에 원인이 스크립트 파일임이 갈렸다. **UTF-8 BOM**을 붙여 해결.

둘 다 **터미널 표시가 아니라 ntfy에서 되읽어** 확인했다 —
`skills/common/powershell-encoding`이 말하는 그대로다. *"터미널 표시만 보고 판단하지 마라."*

## 알림이 가는 곳

`server/appsettings.json`의 `Ntfy.Topic`. 스크립트가 그 값을 읽으므로
토픽을 바꾸면 감시자도 따라간다 — **두 벌로 두지 않는다.**

## 끄는 법

```powershell
Unregister-ScheduledTask -TaskName 'CoordinatorHeartbeatWatch' -Confirm:$false
```

# 원격 깨우기 (`coordinator-wake.ps1`)

## 왜 있는가

**조율자는 채팅 메시지가 와야 턴이 시작된다.** 대화 채널에 글을 남겨도, 작업이 남아 있어도
스스로 다시 돌지 않는다. 사용자는 폰에서 대시보드에는 붙을 수 있지만 **조율자를 깨울 수 없었다** —
집 컴퓨터 앞에 있어야 했다.

그리고 2026-07-27의 334분 공백이 보여준 것: **그건 루프가 아니라 응답이었다.**
할 일이 남아 있었는데 아무도 이어가지 않았다.

## 방아쇠 넷 — 우선순위 순

| 순위 | 방아쇠 | 무엇 | 모드 |
| --- | --- | --- | --- |
| 1 | **검토 대기** | `WORK-QUEUE.md`의 `- [~]` 항목 | **판정** |
| 2 | **안 읽은 대화** | `discussions.json`에 `readBy`가 없는 사람 글 | 실행 |
| 3 | **작업보드** | team-loop `tasks.json`의 활성 태스크 | 실행 |
| 4 | **작업 큐** | `WORK-QUEUE.md`의 `- [ ]` 항목 | 실행 |

넷 다 없으면 `nothing-to-do`.

**판정이 실행보다 먼저다.** 판정이 안 나면 그다음 실행이 무엇 위에 쌓이는지 아무도 모른다.

## 프롬프트가 두 벌인 이유

**한 벌이면 실행자가 자기 일을 자기가 통과시킨다.**

| 모드 | 프롬프트가 시키는 것 |
| --- | --- |
| `execute` | 항목 하나를 하고 **`- [~]`까지만** 옮긴다. `- [x]`로 넘기지 않는다. |
| `review` | 새로 만들지 않는다. **하네스를 직접 재실행해 대조**하고 `- [x]` 또는 `- [ ]`로 판정한다. |

이것이 `LLM_Runtime_Society_V4`의 Court/Clerk 분리다 —
*"법원은 새로운 아이디어를 생성하지 않는다. 선택과 판결만 수행한다."*

그래서 **조율자는 리뷰에서만 깨어나면 된다.** 실행은 CLI 세션과 로컬 모델이 돌린다.

### 실측 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| `- [~]` 1건 + 하트비트 40분 | `would-wake trigger=review=1 mode=review` |
| `- [~]` 0건, `- [ ]` 4건 | `would-wake trigger=queue=4 mode=execute` | **조율자가 이미 돌고 있으면 깨우지 않는다**(하트비트 **10분** 미만 — 25분이면 24분 공백을 살아 있다고 읽었다) —
두 세션이 같은 저장소를 만지면 커밋이 엉킨다.

## 끝나면 스스로 다음을 부른다

한 항목이 끝나면 큐를 다시 세고 **남아 있으면 즉시 다음 세션을 띄운다.** 스케줄러를 기다리지 않는다.

**멈추는 조건 셋** — 무한 재시도로 토큰만 태우는 것을 막는다:

- `queue-drained` — 남은 항목이 없다
- `chain-limit` — 연쇄 5회에 도달했다
- **`no-progress`** — 큐가 줄지 않았다. 같은 항목을 또 시도하면 같은 자리에서 막힌다. **exit 4로 멈추고 사람을 기다린다.**

## 깨어난 세션의 성격

**이 대화의 기억이 없는 다른 세션이다.** 인수인계 문서로만 이어붙는다 —
`RUNTIME-INDEX.md` → `WORK-QUEUE.md` → 안 읽은 대화 순으로 읽는다.
그래서 **큐에 "무엇을·완료 조건·주의"를 적어두는 것이 곧 인수인계**다.

## 인코딩 함정 (셋째)

**프롬프트를 명령행 인자로 넘기면 한글이 깨진다.** 실측: 깨어난 세션이 `"?덈뒗"`을 받고
"입력이 깨져서 들어왔다"고 답했다. **UTF-8 파일을 stdin으로** 넣으면 온전하다.

```
-ArgumentList @('-p', $prompt, ...)          → 깨짐
-ArgumentList @('-p', ...) -RedirectStandardInput $promptFile  → 온전
```

## 실측 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| 안 읽은 글 1건 + 하트비트 40분 | `would-wake trigger=unread=1` |
| 실제 실행 | 세션이 떠서 `readBy` 추가 + 답글 + **지시 밖 작업 안 함**(다른 14건 그대로) |
| 조율자가 도는 중 | `coordinator-alive age=0m` — 안 깨움 |
| 큐 4건 남음 | `would-wake trigger=queue=4` |

## 끄는 법

```powershell
Unregister-ScheduledTask -TaskName 'CoordinatorWake' -Confirm:$false
Unregister-ScheduledTask -TaskName 'CoordinatorHeartbeatWatch' -Confirm:$false
```

# 스크립트 인코딩 검사 (`check-script-encoding.ps1`)

**한글이 든 `.ps1`에 UTF-8 BOM이 없으면 exit 1.**

## 왜 검사가 되었나

같은 함정을 **하루에 세 번** 밟았다. 셋째는 편집 도구가 BOM을 조용히 떼어냈고,
PowerShell이 ANSI로 읽어 한글이 깨지면서 **없는 `}`가 66번째 줄에서** 났다.
나는 문법을 의심하며 블록을 하나씩 잘라 파싱했고, 전부 따로는 통과하는데 합치면 실패했다.
원인은 문법이 아니라 **파일 첫 3바이트**였다.

**규칙으로 두면 또 밟는다.** 그래서 검사로 올렸다 —
이 저장소의 판단 기준 그대로다: *"프롬프트로 시키지 말고 코드로 강제하라."*

## 실측 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| 도입 즉시 | **기존 위반 1건 적발** — `scripts/setup-ollama.ps1`이 BOM 없이 들어와 있었다 |
| BOM 뗀 파일 하나 추가 | `ps1-bom missing=2`, exit **1** |
| `-Fix` 후 재검사 | `ps1-bom ok`, exit **0** |

한글이 없는 `.ps1`은 BOM이 없어도 안 깨지므로 검사하지 않는다 — 안 깨지는 것을 막으면
검사가 잔소리가 되고, 잔소리는 무시된다(FAIL-2026-010).

CI 윈도우 잡의 **build보다 먼저** 돈다. 싸고, 여기서 걸리면 뒤가 다 무의미하다.

# 6시간 47분 정지 — 안전망 둘이 같은 결함을 공유했다 (2026-07-27)

## 무슨 일이 있었나

깨우기 루프는 **실제로 돌았다.** 12:11~14:05에 판정 1건 통과, `buildSkillPolicy` 실행과 병합,
그 판정까지 마치고 사람 게이트에서 정확히 멈췄다. 여기까지는 설계대로다.

그 뒤 **14:05부터 20:52까지 6시간 47분** 동안 아무 일도 없었다.

## 원인

깨어난 세션 하나가 하트비트를 **미래로** 찍었다. `at`이 `2026-07-27T22:47:00+09:00`,
즉 그 시점보다 앞선 시각이었다. 로컬 시각에 오프셋을 한 번 더 적용한 것으로 보인다.

그러면 `age`가 **음수**가 된다. 그리고 두 스크립트가 똑같이 이렇게 판정하고 있었다:

```powershell
if ($age -lt $StaleMinutes) { "alive"; exit 0 }
```

`-236 < 10`은 참이다. **음수는 전부 "살아 있다"로 통과했다.**

- `coordinator-wake.ps1` → 영원히 "조율자가 돌고 있다"고 판단, 안 깨움
- `coordinator-heartbeat-watch.ps1` → **같은 줄**, 그래서 ntfy 알림도 안 감

**안전망이 둘 있었는데 같은 검사를 공유해서 한꺼번에 눈을 감았다.**
독립적이지 않은 이중화는 이중화가 아니다.

## 고친 것

| 무엇 | 어떻게 |
| --- | --- |
| 음수 나이 | **fail-closed** — 미래 하트비트는 살아 있다의 증거가 아니라 고장의 증거로 읽는다 |
| 읽기 실패 | 마찬가지로 깨운다. 모르는 것은 통과가 아니다 |
| 감시자 | 미래 하트비트를 **최고 우선순위(5)** 알림으로. 조용한 것보다 나쁘다 |
| 쓰는 쪽 | 프롬프트에 형식 계약을 박았다 — **UTC, `Z`로 끝날 것** |
| `board-stuck` 방아쇠 | 없앴다. `[사람 게이트]` 태스크까지 세서 아무도 집을 수 없는 일로 깨우고 `no-progress`로 끝났다 |

### 실측 (수리 직후, 미래 하트비트를 그대로 둔 채)

| 스크립트 | 결과 |
| --- | --- |
| `coordinator-wake.ps1 -DryRun` | `heartbeat-in-future skew=111m - 고장으로 보고 깨운다` → `would-wake` |
| `coordinator-heartbeat-watch.ps1 -DryRun` | `would-alert: 하트비트가 111분 미래로 찍혀 있다...` |

## 남는 교훈

**살아 있음을 하나의 숫자 비교로 판정하면 그 숫자가 망가질 때 조용히 죽는다.**
`age < N`은 `age`가 항상 0 이상이라는 가정을 품고 있었고, 그 가정이 어디에도 안 적혀 있었다.
CLAUDE.md가 말하는 *"판정은 exit code로"*와 같은 결이다 — **가정을 검사로 바꿔라.**

# 세션 격리 (`session-lock.ps1` + `.githooks/`)

## 왜 있는가

2026-07-27, **두 세션이 같은 작업 트리를 동시에 만졌다.** 실행 세션이 `NET8-01-R1`을 하는 동안
판정 세션이 같은 항목을 판정하고 있었고, 실행 세션의 `git add -A`가 **판정 세션의 파일을
자기 커밋에 쓸어 담았다**(`c081dc4`, `9bfda28`). 커밋 메시지와 내용이 어긋났다.

깨우기의 하트비트 검사는 이걸 못 막았다 — 그 세션은 **깨우기가 띄운 게 아니었다.**
하트비트 계약 밖에 있는 세션은 하트비트로 막을 수 없다.

**프롬프트로 "동시에 하지 마라"고 적는 것으로는 안 지켜진다.** 그래서 코드가 막는다.

## 어떻게 판정하나

**프로세스 생사다. 시각이 아니다.**

잠금 파일(`C:\NHN Project\_ops\coordinator.lock`)이 주인 세션의 `claude.exe` pid를 들고 있다.
스크립트는 자기 조상 사슬을 거슬러 올라가 `claude.exe`를 찾아 자기 세션을 식별한다.
**주인이 죽어 있으면 자동으로 회수한다** — 세션이 비정상 종료해도 루프가 영구히 막히지 않는다.

## 언제 쥐고 언제 놓나

**커밋 구간에만 쥔다.**

| 시점 | 동작 |
| --- | --- |
| `pre-commit` | 다른 살아있는 세션이 주인이면 **커밋 거부**. 비어 있으면 잡는다 |
| `post-commit` | 놓는다 |
| `coordinator-wake.ps1` | 잠금이 남의 것이면 `session-locked`로 **안 깨운다** |

세션이 살아 있는 내내 쥐면 안 된다 — `claude.exe`는 세션 내내 살아 있어서
**깨우기가 영원히 막힌다.** 그건 이번에 만들다가 발견해서 고쳤다.

**사람이 손으로 하는 커밋은 안 막는다.** 조상 사슬에 `claude.exe`가 없으면 그냥 통과한다.

## 실측 (2026-07-27)

| 상황 | 결과 |
| --- | --- |
| 잠금 없음 | `lock-free me=23748`, exit 0 |
| 획득 후 | `lock-mine pid=23748`, exit 0 |
| **살아있는 다른 세션이 주인** | `lock-held-by-other owner=11460 me=23748`, exit **1** |
| **그 상태에서 실제 `git commit`** | **거부됨.** `HEAD` 안 움직임 |
| 죽은 세션이 주인 | `lock-reclaimed` → `lock-free`, exit 0 |

## 이것이 막는 것과 못 막는 것

**막는다**: 두 세션이 **동시에 커밋**하는 것. 그래서 남의 파일을 쓸어 담는 사고가 커밋으로 확정되지 않는다.

**못 막는다**: 두 세션이 **동시에 편집**하는 것 자체. 잠금은 커밋 구간에만 걸리므로,
편집이 겹치는 창은 여전히 열려 있다. 완전한 격리는 **워크트리 분리**가 필요하고
그건 `WORK-QUEUE.md`에 남겨뒀다. **이건 절반의 해결이다 — 그렇게 알고 써라.**

## 설치

훅은 `.githooks/`에 있고 저장소에 들어간다. 새 클론에서 한 번:

```bash
git config core.hooksPath .githooks
```

# 큐의 "진행 중" 상태 (`queue-state.ps1`)

## 왜 있는가

큐에 `- [ ]`·`- [~]`·`- [x]`만 있고 **그 사이가 없었다.** 그래서 2026-07-27에
**두 세션이 같은 항목을 동시에 집었다** — 한 세션이 세션 격리를 만드는 동안
다른 깨어난 세션이 같은 항목을 잡고 같은 잠금을 시험하고 있었다.

## 규칙

**`- [>]`는 손으로 쓰지 않는다.** 프로그램이 찍고 프로그램이 회수한다.

```
- [>] **항목 제목** — 진행 중 (session=12345, since=2026-07-27T13:02:52Z)
```

| 시점 | 동작 |
| --- | --- |
| 깨우기 시작 | `Sweep` — 주인이 **죽은** `[>]`를 `[ ]`로 되돌리고 로그에 남긴다 |
| 세션 띄운 직후 | `Claim` — 맨 위 `[ ]`를 `[>]`로 찍고 그 세션 pid를 박는다 |
| 세션이 끝나면 | 세션이 `[~]`로 옮긴다. 안 옮겼으면 다음 `Sweep`이 `[ ]`로 회수한다 |

**낡은 `[>]`가 항목을 영구히 붙잡으면 그게 더 나쁘다.** 영구히 막힌 것은 무시된다(FAIL-2026-010).
그래서 판정은 **프로세스 생사**다 — 시각이 아니다.

파일을 통째로 다시 쓰지 않고 **해당 줄만** 바꾼다. 재작성은 저장소에 박힌 깨진 한글을 퍼뜨린다.
