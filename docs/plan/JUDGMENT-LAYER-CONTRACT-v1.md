# 판정층 계약 v1 — 흡수하는 쪽이 받을 것

> **이 문서가 넘어가는 것이다. C# 코드는 안 넘어간다.**
> 근거: `docs/handoff/decisions/ADR-018-fusion-into-team-loop.md`.
> 흡수 방향은 team-loop이 받는 쪽이고, 형태는 "오케스트레이션은 team-loop, 판정층은 흡수"다.

판정층은 **코드가 아니라 두 가지**다: **데이터 계약**(§2)과 **규칙**(§3).
아래 모든 항목은 **git·JSON·markdown·프로세스 실행**만으로 성립하며 언어에 묶이지 않는다.

## 1. 실측 — 무엇이 실제로 언어에 묶여 있나

게이트 3종의 **서로 다른 명령 14개**를 분류했다(2026-07-27).

| | 개수 | 명령 |
| --- | --- | --- |
| **언어 무관** | **11** | `gate-clean` `handoff-integrity` `context-pack-integrity` `doc-integrity` `gate-witness-check` `launch-disposition` `territory-check` `hs-scan` `state-transition-selftest` `recovery-selftest` `trust-origin-selftest` |
| **C# 특정** | **3** | `measure` `build-verify` `verify-behavior` |

- **`POST-COMMIT`은 22검사 전부가 언어 무관 명령이다.** C# 특정 명령이 **0개**다.
- C# 특정 3개도 대응물이 자명하다: `build-verify` → 그쪽 `npm run check`,
  `measure` → 그쪽 blueprint/지표 측정, `verify-behavior` → 동작 스냅샷 비교.
- 구현 규모는 `server/Harness/` **23파일 5,417줄**이다. 이건 **다시 쓸 양**이지
  옮길 양이 아니다.

**결론: 어려운 것은 이식이 아니라 §4의 결정이다.**

## 2. 데이터 계약 — 이미 언어 중립인 것들

### 2-1. 게이트 매니페스트

```json
{ "schemaVersion": 1,
  "gates": [{
    "gateId": "POST-COMMIT",
    "description": "…", "triggeredBy": "…",
    "requireFailureWitness": true,
    "checks": [{
      "order": 1, "command": "gate-clean", "args": ["server"],
      "expectedExit": 0, "mutatesState": false,
      "note": "…실측 날짜와 수치…",
      "internalNegativeCases": 15,
      "negativeWitness": 9
    }],
    "unregisteredChecks": [{ "command": "scope-check", "reason": "…왜 못 넣는가…" }]
  }]}
```

- **`expectedExit`가 판정의 전부다.** 출력 문자열·정규식으로 성패를 세지 않는다.
- **`expectedExit`가 0이 아닌 항목이 반증 witness다.** 같은 명령의 비영 종료, 또는
  `negativeWitness`로 order를 지목, 또는 `internalNegativeCases`(§3-2).
- **`unregisteredChecks`는 빈칸이 아니라 사유다.** 판정할 수 없는 검사는 넣지 않되
  **왜 못 넣는지를 남긴다.** 빠진 것과 뺀 것을 구분하기 위해서다.

### 2-2. 게이트 보고

```json
{ "gateId": "…", "verdict": "PASS|FAIL",
  "baselineCommit": "<40자 sha>", "worktreeCleanAtStart": true,
  "launchId": "<선택 — 어느 실행을 잰 것인가>",
  "checks": [{ "order": 1, "command": "…", "args": [],
               "expectedExit": 0, "actualExit": 0,
               "startedAt": "…", "durationMs": 0,
               "verdict": "PASS|FAIL", "stdoutTail": "…", "stderrTail": "…" }] }
```

`stdout`/`stderr`는 **진단 증거이지 판정 근거가 아니다.** 판정은 `expectedExit == actualExit`.

### 2-3. 처분 기록 (자동 실행 산출물의 반입 여부)

```json
{ "launchId": "…", "state": "pending|imported|rejected",
  "decidedAt": "YYYY-MM-DD", "actor": "누가 정했는가",
  "importCommit": "<imported일 때 필수>",
  "gateReport": "<imported일 때 필수 — 그 launchId를 담은 보고 경로>",
  "reason": "<rejected일 때 필수>" }
```

- **발사하면 `pending`이 자동 생성된다.** 사람이 정할 때까지 게이트가 빨갛다 — 의도된 동작이다.
- `imported`는 `importCommit`이 실재 커밋이어야 하고, `gateReport`의 `baselineCommit`이
  그 커밋의 **후손**이어야 한다. **반입보다 앞선 보고는 그 반입의 증거가 아니다.**

### 2-4. 컨텍스트 팩 (지시서 머리)

```json
{ "diId": "…",
  "requiredInputs": [{ "path": "…", "sha256": "…" }],
  "readOrder": ["…"],
  "forbiddenActions": ["commit","push","approve","reject","import"] }
```

- **`sha256`은 프로그램이 계산한다. 사람도 LLM도 적지 않는다.** 손으로 적으면 검증이 아니라 창작이다.
- **`requiredInputs`(읽기)와 쓰기 allowlist는 겹치지 않는다.** 작업 중 바뀌는 파일에 해시를 걸면
  게이트가 자기 작업에 걸려 넘어진다.

## 3. 규칙 — 검사 가능한 형태로

각 규칙에 **왜(실측)** 와 **어떻게 재는가**를 붙였다. 실측 근거는 이 저장소
`docs/verification/` 아래에 있다.

### 3-1. 면제는 **경로**가 아니라 **그 커밋의 반입**에 묶는다

- **왜**: 경로 기준이면 *"자동화가 한 번이라도 만진 파일은 그 뒤로 사람이 영원히 자유롭게 고칠 수
  있다."* 실측 — 같은 커밋에 대해 위반이 **2 → 3**으로 늘었다(경로 기준일 때 1건이 부당 면제).
- **계약**: 보호 영역 경로 `P`가 커밋 `X`에서 바뀌었을 때 다음 중 하나여야 면제한다.
  1. **자기 증명** — `X`가 **추가한** 산출 패치가 `P`를 담는다(이미 있던 패치는 근거가 아니다).
  2. **처분 결속** — `state == imported` 이고 `importCommit == X` 인 기록의 패치가 `P`를 담는다.
  3. **사람 승인** — 면제 대장에 `X`가 사유와 함께 있다.
- **주의**: 반입은 **두 커밋에 걸친다**(`importCommit`을 미리 알 수 없다). 1번만 두면 재적용
  커밋이 막히고, 2번만 두면 반입 커밋 자신이 막힌다. **둘 다 필요하다.**
- **`rejected` 처분의 패치는 근거가 아니다.** 단 1번에는 이 조건을 걸지 마라 —
  반입 시점의 처분은 정의상 `pending`이다.
- **HEAD 커밋 하나만 본다.** 이력 전체를 훑으면 과거 때문에 영구 적색이 된다(§3-6).

### 3-2. 등재되지 않은 픽스처는 시험이 아니다

- **왜**: 낡은 값 `20`을 단 픽스처가 **어느 게이트에도 안 물려 아무도 실행하지 않았다.**
  값이 틀린 채로 저장소에 남아 있었다.
- **계약**: 반증 픽스처를 만들면 **매니페스트에 등재한다.** 등재 전에 **기대 exit code를 실측**하고
  `note`에 날짜와 수치를 적는다. **추정으로 기대값을 적지 않는다.**
- **`internalNegativeCases`는 실측과 정확히 같아야 한다(`==`, `>=` 아님).**
  `>=`면 **적게 적을수록 쉽게 통과**해서 숫자가 실재보다 작아지는 표류를 아무도 못 잡는다.
- 그 수치를 읽을 때는 **최상위 문서에 선언된 값 하나만** 인정한다. 출력 전체의 최댓값을 취하면
  요약이 아니라 깊이 박힌 큰 수가 답이 된다. **문서가 여럿이면 어느 것이 요약인지 알 수 없다 —
  모르면 증거가 아니다.**

### 3-3. 표를 실재에 못 박는다 — 선언과 실측을 구분한다

- **왜**: 생산자와 검사자가 **같은 표를 읽어** 대조가 공회전이었다. 케이스를 늘려도 줄여도 통과했다.
  같은 부류로 `HighRiskFailClosed()`가 `=> true` 상수였고, 투영 명령이 no-op이었다.
- **계약**: 어떤 수치를 evidence에 적을 때, **그 값을 검사하는 쪽은 다른 출처에서 와야 한다.**
  선언표를 두는 것은 좋지만 **그 표가 실재와 맞는지 재는 검사가 따로 있어야 한다.**
- **재보지 않은 주장은 증거가 아니다.** 옵션 하나로 검증을 건너뛰게 만들지 마라 —
  건너뛰면 그 게이트는 문면 숫자만으로 통과한다.
- **실패값은 `0`이 아니라 `-1`(미측정)로 구분한다.** `0`은 "세어봤더니 없더라"다.

### 3-4. exit code로 증명되지 않는 수정이 있다 — 그때는 수치를 본다

- **왜**: 3-1의 수정은 **수정 전후 exit code가 둘 다 1**이었다. "판정은 exit code로"라는 원칙만
  따랐으면 **아무것도 안 보였을 것이다.**
- **계약**: 게이트 통과 여부는 exit code로 판정하되, **변경이 무엇을 바꿨는지 보이려면 구조화 수치**
  (`violations`, `coveredByOutbox`, `casesRun`)를 함께 낸다. 지시서에 **무엇으로 판정할지 명시한다.**
- **짝을 지어라.** "막았다"만으로는 부족하다 — 한 필드만 뒤집어 **"안 막으면 통과한다"**도 보여라.
  실측 예: 처분 `state`를 `rejected`→`imported`로만 바꾸니 면제 0 → 1로 바뀌었다.
  그래야 *"그 입력을 아예 안 읽는 것"* 과 구분된다.

### 3-5. 런타임을 격리해야 "어느 것이 돌았나"가 사실이 된다

- **왜**: CI 잡 이름이 `10.0`인데 **실제로는 8에서 돌고 있었다.** 러너에 여러 버전이 깔려 있었고,
  프로젝트가 8을 겨냥해 정확히 맞는 8이 선택됐다. 로컬이 10에서 돌던 것은 **그 기계의 우연**이었다.
- **계약**: 버전 매트릭스는 **컨테이너로 격리한다.** 이미지 안에 그 버전 하나뿐이면
  "어느 런타임이 돌았나"가 설정이 아니라 **사실**이 된다.
- 잡 로그에 **실제 설치 버전 목록을 찍는다.** 이름은 주장이고 로그가 증거다.
- **버전 하한을 선언한다**(이 저장소는 `global.json`). 없으면 낮은 버전에서 난해한 에러가 난다.

### 3-6. 영구히 빨간 게이트는 무시된다 — 고치기 전에 켜지 마라

- **왜**: 이 저장소의 기록된 실패(FAIL-2026-010).
- **계약**: 준비 안 된 검사는 **넣지 말고, 왜 안 넣었는지 매니페스트에 적는다.**
  이 저장소는 `.NET 8` CI 다리를 **주석과 함께 비워 뒀다** — "잊어서 빠진 게 아니다"와
  "무엇이 이것을 켜는가"를 같이 적었다.
- 새 검사는 **초록으로 도착해야 한다.** 빨간 채로 등재하면 그 게이트 전체가 무시되기 시작한다.

## 4. 넘기기 전에 정해야 할 것 — 여기가 실제 난점이다

1. **상태 원본을 어디에 둘 것인가.** 두 벌로 두면 이 저장소가 하루에 세 번 고친 병
   (같은 정의가 두 벌이라 한쪽만 낡음: `RequiredGateCommands`·`SelfTestGateCounts`·영토 목록)을
   **저장소 규모로 반복한다.** §2의 계약은 이 결정이 서야 얹을 수 있다.
2. **합칠 대상의 범위** — §3 규칙표만인가, §2 데이터 계약까지인가, 판정 실행기까지인가.
3. **판정 실행기를 다시 쓸 것인가.** 매니페스트를 읽고 명령을 돌려 exit code를 대조해 보고를 쓰는
   부분은 작다. **큰 것은 검사 11개의 내용**이고, 그건 이 저장소의 5,417줄에 해당한다.
4. **이 저장소의 처분** — 보존·아카이브·폐기.

## 5. 이 문서의 사본을 만들지 마라

**정의는 한 벌이다.** 흡수하는 쪽으로 옮길 때 **원본을 옮기고 이쪽에는 포인터만 남긴다.**
양쪽에 두면 §3-3이 말하는 바로 그 병에 걸린다.
